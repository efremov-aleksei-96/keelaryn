# VPS MIGRATION — единый исполняемый план KeelarynOS

**Статус:** ACTIVE · 2026-11-15. **Владелец плана реализации:** Keelaryn Engine, репозиторий `efremov-aleksei-96/keelaryn`, ветка `dev/mcp-portability`. **Единственный курсор перехода:** этот файл. `mcp/README.md` содержит инженерные доказательства и ссылку сюда, но не вторую очередь задач. Общие правила — `KEELARYNOS_PROJECT_RULES.md` по официальной ссылке проекта ChatGPT; предметные правила и решения о переключении — только у соответствующих Domain OS/проектов. Этот план **не** делает Keelaryn Engine владельцем чужих данных.

## Результат, который требуется получить

VPS хранит единственные активные версии разрешённых файлов проектов в понятном локальном дереве. MCP даёт ограниченные операции чтения/записи с CAS, журналом и человеческим CLI; всё повторяемое работает без ChatGPT. Google Drive перестаёт быть **операционной зависимостью** канонических проектов и может оставаться внешней резервной копией / историческим оригиналом. **Полный отказ от Google даже для резервирования** — отдельный завершающий выбор независимого хранилища, а не обещание уже достигнутой автономности. GitHub остаётся владельцем исходников Keelaryn Engine, специальные внешние функции — явно описанные исключения.

**Запрещено считать переходом:** простое копирование; подключение read-only snapshot; изменение одного проекта без проверки всех его зависимостей; назначение двух действующих канонов; экспорт из Sheets без сохранения формул, колонок, истории и семантики; проверку на VPS вместо доказанной работы на независимом ПК. **Bankruptcy: MANUAL_LOAD_ONLY** — не открывать, не включать в инвентаризацию содержимого и не переносить без отдельной прямой команды.

## Правило исполнения для любого нового чата и команды «Далее»

1. Открой этот файл, действующие общие правила по ссылке проекта ChatGPT и только затронутые актуальные источники; повторно не читай неизменённое. Перед изменением сверяй реальное состояние. Не требуй ручной работы, если доступен безопасный API.
2. Выбери **первую выполняемую** задачу из таблицы ниже с учётом зависимости и риска. `READY` — выполняй; `BLOCKED` — **запиши конкретный блокер и переходи к следующей независимой задаче в том же ходе**; `DONE` не повторяй; `WAIT` не блокирует параллельные независимые действия. Одновременно не делай массовую миграцию.
3. Для нового предметного владельца: текущий канон → инвентаризация/зависимости → защита исходника → перенос данных → SHA/содержательная сверка и восстановление → **отдельно разрешённое переключение одного владельца** → обычная реальная операция → повторное чтение → единое резервирование. Старые Drive-файлы сохраняй как исторические. Не подменяй отсутствие разрешения общей установкой «всё на VPS».
4. После существенного результата **обнови этот же курсор** (статусы, краткое доказательство, блокер, точный NEXT) и перечитай запись. При неопределённой записи сначала read-only reconcile, никакого слепого повтора. Не делай отчётов и новых параллельных планов.
5. Если нет доступа к одному сервису, источнику или разрешению — переходи к независимой подготовке следующего этапа. **Никогда не трактуй один блокер как остановку всей миграции.** Не обещай фоновую работу: новые ходы начинаются по запросу или через отдельно созданную явную автоматизацию.

## Неподлежащие догадкам факты и ограничения

- VPS: `keelaryn-vps`; один системный MCP сервис и существующий туннель. Текущий общий архив резервирует только зарегистрированные **VPS-canonical** owner-fs деревья, а не «все файлы Google». Режим других областей read-only; `KeelarynEnginePilot` неканонический.
- Drive исходного рабочего дерева: проверять точную цепочку parent IDs. `My Laptop/2__Project` — **кандидат**, а не автоматически весь актуальный канон. `8__Library` (`12a3FcR1NLtEVmkOjAJe1g_RI1A5VMtBJ`) — соседняя папка того же родителя. Другие `2__Project` найдены в GoogleNative/архивах; не смешивать.
- MusicLibrary: только два файла уже переключены. Registry Sheets, оригинальные медиа, специальные музыкальные контракты — ещё Google; решения KEEP/DELETE и курсор — у Registry. Запретный Bankruptcy исключён без нового прямого разрешения.
- Защита секретов обязательна. Общий таймер уже существует; не создавать по таймеру на проект. Не генерировать многочисленные README/STATE/WORKLOG, ZIP и копии только ради плана.
- Предметная истина остаётся у Domain OS/проекта; этот список отражает **только инженерное продвижение** и не конкурирует с LifeOS.
