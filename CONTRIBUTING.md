# Contributing

Read `KEELARYN_CANONICAL.md` and `DEVELOPMENT_STATE.json` first.

Before adding a non-trivial subsystem, survey mature standards and open-source implementations. Prefer reuse/wrapping/integration over replacement code. Preserve Keelaryn identity invariants, ambiguity semantics and the minimal P0 build order.

Do not resurrect legacy Hub/Manager architecture as current authority.
